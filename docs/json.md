# Контракт JSON

## Формат

Корень файла является объектом с обязательным `schemaVersion: 1`. Полный набор ключей и типов определён в [application.schema.json](../schema/application.schema.json). Метаданные реализации находятся в [contract.js](../extension/shared/contract.js); проверка и нормализация выполняются в [validator.js](../extension/shared/validator.js).

Все группы и поля анкеты необязательны. Неизвестные ключи и версии отклоняются. Файл проверяется в сайдбаре и повторно в сеансе страницы. Ошибка JSON блокирует запуск, включая загрузку выбранных фотографий.

| Группа | Содержимое |
| --- | --- |
| `personal` | Личные данные, гражданство, email, прежние паспорта и нарушения |
| `passport` | Основной паспорт и другие действующие паспорта |
| `visa` | Кратность въезда и сроки действия визы |
| `contact` | Адреса, телефон и контактное лицо |
| `occupation` | Занятость и организация |
| `trip` | Поездка, пункты въезда и выезда, адрес, контакты, поездки и родственники |
| `expenses` | Расходы, страхование, плательщик и спонсор |

Основной сценарий: один JSON и один запуск заполнения. Предыдущее содержимое формы не защищается от замены заданными значениями или от реакций сайта.

## Значения и ограничения

- Отсутствующий ключ, `null`, пустая строка и строка из пробелов пропускаются. Пустой массив не изменяет список. Если заданных значений и пригодных фотографий нет, запуск не начинается.
- `false` и `0` являются заданными значениями. Длительность поездки является положительным целым числом; расходы являются неотрицательным конечным числом.
- При импорте строки очищаются от крайних пробелов. Внутренние пробелы текстовых значений сохраняются.
- Даты имеют формат `YYYY-MM-DD` и должны существовать в календаре. Часовой пояс не используется для преобразования дат анкеты.
- `personal.dateOfBirth` и `personal.yearOfBirth` взаимоисключающие. Год является целым числом от 1000 до 9999. Дополнение выбирает соответствующий режим на сайте.
- `personal.email` заполняет Email и Re-enter Email. Ключ `confirmEmail` не поддерживается.
- Варианты выбора задаются английскими названиями на сайте. Сопоставление допускает различия регистра и пробелов. Подстроки и приблизительные совпадения не используются. Отсутствующий или неоднозначный вариант считается ошибкой поля.
- Телефоны, номера паспортов и идентификаторы являются строками; ведущие нули и знак `+` сохраняются.
- Дата окончания не может предшествовать дате начала для основного паспорта, визы, других действующих паспортов и прошлых поездок.
- `expenses.hasInsurance: false` нельзя сочетать с непустым `insuranceDetails`.

Отсутствие обязательного для сайта поля не является ошибкой частичного JSON. Проверка JSON не заменяет проверку анкеты сайтом. Фотографии выбираются отдельно; в JSON нет путей к файлам, cookies, селекторов или исполняемого кода.

## Повторяющиеся записи

| Управляющий флаг | Связанный массив |
| --- | --- |
| `personal.hasOtherNationalities` | `personal.otherNationalities` |
| `personal.hasUsedOtherPassports` | `personal.previousPassports` |
| `personal.hasViolations` | `personal.violations` |
| `passport.hasOtherValidPassports` | `passport.otherValidPassports` |
| `trip.hasVietnamContacts` | `trip.vietnamContacts` |
| `trip.hasVisitedWithinLastYear` | `trip.previousVisits` |
| `trip.hasRelativesInVietnam` | `trip.relativesInVietnam` |

Непустой массив заменяет соответствующий список в указанном порядке и подразумевает `true` для флага. Явно заданный `false` вместе с непустым массивом отклоняется. Для ответа «Нет» достаточно задать флаг `false`.

`otherNationalities` содержит непустые строки выбора. Остальные массивы содержат полные записи с полями из JSON Schema. Все поля записи обязательны и непусты, кроме `typeDetails` в `otherValidPassports`. Пустые объекты и пустые элементы внутри непустого массива не создают пустых строк.

Строки добавляются и заполняются последовательно. Лишние прежние строки удаляются только после проверки всех целевых строк. Частично выполненный список не откатывается; ошибки отражаются для списка и отдельных ячеек.

## Экспорт

Экспорт читает текущую форму без записи на сайт. Файл содержит все поля схемы, включая пустые строки, пустые массивы и `null` для невыбранных значений, с такими исключениями:

- При `false` у любого флага из таблицы связанный массив не считывается и не включается в JSON.
- При `expenses.payer: "Personal"` объект `expenses.sponsor` не считывается и не включается в JSON. Сравнение допускает различия регистра и крайних пробелов.

Для даты рождения сохраняется активный режим; значение второго режима равно `null`. Корректные даты переводятся в `YYYY-MM-DD`, числовые значения в числа. Пробелы и некорректные черновые значения известных inputs сохраняются без исправления. Строки списков сохраняются в текущем порядке.

Ошибки проверки данных не мешают сохранению: сайдбар показывает предупреждения. Если поле не удалось прочитать, сохраняется пустое значение с предупреждением. Несовпадение Email и Re-enter Email также вызывает предупреждение, но подтверждение email в файл не включается. Исключённые неактивные разделы предупреждений не создают.

Фотографии и галочка обязательства о временном проживании не экспортируются. Черновик с ошибками нужно исправить перед импортом. Пустые значения при импорте пропускаются; экспорт не является командой очистки формы.

Имя `evisa-YYYY-MM-DD.json` использует локальную дату компьютера на момент открытия диалога сохранения. Отмена сохранения не считается ошибкой.
