# Разработка и проверки

## Локальная среда

Дополнение загружается из [extension/manifest.json](../extension/manifest.json) без сборки. Для тестов нужны Node.js и npm.

```powershell
npm ci
npm test
```

Тесты используют встроенный runner Node.js; Ajv проверяет JSON Schema. Для краткого вывода:

```powershell
node --test --test-reporter=dot
```

## Покрытие

Каталог [tests/](../tests/) содержит проверки JSON Schema и нормализации, маршрутов и сеанса, нативного чтения и записи, замены строк, зависимостей, фотографий, остановки, таймаутов, сайдбара и экспорта. Проверки экспорта включают пустые значения, неактивные разделы, локальную дату файла, сохранение и отмену.

Локальные DOM fixtures проверяют модули и не воспроизводят сервер сайта. Для проверки интеграции используется Firefox с текущей формой. Примеры и тестовые данные должны оставаться вымышленными.

## Проверка в Firefox

После изменения файлов нажмите **Reload / Перезагрузить** в `about:debugging#/runtime/this-firefox`, обновите вкладку формы и откройте сайдбар заново. После перезапуска Firefox временное дополнение загружается повторно.

1. Откройте английскую новую личную форму.
2. Выберите один JSON. Проверьте обычные и зависимые поля, списки и заполнение обоих Email значением `email`.
3. При необходимости загрузите одно или два изображения. Ошибки загрузки должны отображаться, а отсутствие второго изображения не должно мешать JSON.
4. Проверьте паузу при открытом диалоге сайта и остановку заполнения.
5. Сохраните форму в JSON. Проверьте пустые значения и исключения по [контракту](json.md). Отмена диалога не должна показывать ошибку.
6. Исправьте предупреждения черновика и используйте файл для заполнения новой формы.
7. Переключитесь на сохранённую заявку `/e-visa/foreigners/<идентификатор>?email=...`. Проверьте, что видна только панель сохранения в JSON и экспорт работает. Вернитесь на новую форму и проверьте, что панель заполнения появилась снова. Повторите проверку при смене адреса в той же вкладке.

## Изменение кода

Для изменения контракта синхронизируются `shared/contract.js`, `shared/validator.js`, JSON Schema, примеры и документация. Для изменения DOM-сопоставления используются известные нативные элементы и проверки принадлежности форме. Тесты должны проверять пользовательское поведение и реальные границы модулей.

Рабочие данные пользователей и результаты экспериментов не включаются в документацию и тестовые fixtures. История реализации хранится в Git; текущие документы не являются журналом разработки.
